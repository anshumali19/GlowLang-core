# GlowLang Package Authoring Guide

## Package Structure

A GlowLang package is a single `.glow` file or a directory with a main entry point:

```
my_package/
├── my_package.glow    # Main entry point
├── Glow.deps          # Dependencies (if any)
└── README.md          # Documentation
```

## Glow.deps Format

```
# Dependencies — one per line
# Format: name@version (optional_url)
web@^1.0.0
tensor@~1.0.0
json@latest
custom_lib@1.2.3 (https://example.com/custom_lib.glow)
```

### Version Constraints

| Prefix | Meaning | Example |
|--------|---------|---------|
| `^` | Compatible (same major) | `^1.2.0` matches `1.2.0` through `1.99.99` |
| `~` | Approximate (same minor) | `~1.2.0` matches `1.2.0` through `1.2.99` |
| `>=` | Minimum version | `>=1.0.0` |
| `latest` | Latest available | Always resolves |

## Publishing

```bash
# Validate the package
gdu verify my_package

# Publish to the registry
gdu publish my_package 1.0.0
```

## Using Your Package

Others can install it with:

```bash
gdu add my_package 1.0.0
```

Then use it in their code:

```glow
use "my_package"
```

## Lockfile (Glow.lock)

Generated by `gdu (Glow Dependency Utility) resolve`. Contains pinned versions with SHA-256 checksums:

```
# GlowLang Dependency Lock File
web@1.2.0 sha256:a1b2c3d4...
tensor@1.0.0 sha256:e5f6a7b8...
```

**Never edit Glow.lock manually.** Run `gdu (Glow Dependency Utility) resolve` to regenerate.
